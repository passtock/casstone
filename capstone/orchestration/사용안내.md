# 캡스톤 Codex 사용 안내

캡스톤 프로젝트의 총괄 작업에 평소처럼 요청하면, 공통 지침에 따라 필요한 담당자에게 위임하는 구성입니다. 항상 세 명을 모두 호출하는 구성은 아닙니다.

| 역할 | 모델 | 추론 |
|---|---|---|
| 총괄 | GPT-6 Astra | medium |
| 연구설계 research_planner | GPT-6 Astra | medium |
| 실험구현 experiment_engineer | GPT-6 Astra | low |
| 발표/문서작성 presentation_builder | GPT-6 Astra | low |

## 시작 방법
1. 설치된 설정을 불러오도록 캡스톤 폴더에서 새 Codex 작업을 시작합니다. 필요하면 앱을 다시 엽니다.
2. 앱의 모델 선택이 프로젝트 기본값보다 우선할 수 있으므로 총괄 작업 모델이 Astra인지 확인합니다.
3. 예: “현재 연구계획을 읽고 research_planner에게 실험설계를 검토시켜줘.”
4. 예: “확정한 실험 명세를 experiment_engineer에게 맡겨 코드를 구현하고 테스트해줘.”
5. 예: “검증된 결과로 presentation_builder에게 교수님 발표용 10분 PPT를 만들어 달라고 해줘.”
6. 통합 요청도 가능합니다: “연구계획과 코드를 검토해서 필요한 담당자에게 나누고, 검증된 내용으로 발표까지 만들어줘.”

## 파일의 역할
- 프로젝트 루트 AGENTS.md: 배정, 인계, 검증 공통 규칙.
- .codex/config.toml: 총괄 기본 모델과 동시 담당자 수.
- .codex/agents/*.toml: 세 담당자의 모델과 역할.
- orchestration/STATUS.md: 총괄이 갱신하는 현재 상태.
- orchestration/DECISIONS.md: 기준 변경 이유와 결정 기록.
- orchestration/templates/EXPERIMENT.md: 실험마다 복사해서 쓰는 명세·실행 기록.
- orchestration/setup/: 설치 설정의 검토용 원본. 실제 적용 설정은 .codex/ 아래입니다. 이후 설정 변경은 실제 적용 파일과 이 원본을 함께 맞춥니다.

## 운영 범위
이 구성은 요청할 때 담당자를 호출하는 프로젝트 설정입니다. 예약 실행이나 상시 백그라운드 실행은 설정하지 않았습니다.
스킬은 별도 모델이 아니라 제작 절차입니다. PPT 담당은 사용 가능한 presentations 스킬을 이용합니다.
프로젝트 신뢰 상태나 앱 정책으로 로컬 설정이 로드되지 않으면 해당 안내에 따라 프로젝트를 신뢰한 후 새 작업에서 확인합니다. 설정 파일이 있다는 사실만으로 모델 호출 성공을 보장하지 않습니다.
실제 연구 실행 및 모델별 호출 확인은 별도 작업입니다. 아직 측정되지 않은 데이터는 결과로 만들지 않습니다.
