# 캡스톤 연구 오케스트레이션

## 공통 원칙
- 한국어로 설명하고 사용자의 현재 요청을 우선한다. 기존 연구자료와 코드를 먼저 확인한다.
- 이 프로젝트는 총괄이 연구설계, 실험구현, 발표 담당에게 필요한 작업을 위임하는 운영을 사용한다.
- 총괄 기본 모델은 gpt-6-astra / medium. 총괄은 요청 분류, 인계, 최종 검증과 사용자 보고를 책임진다.
- 단순 질문이나 작은 수정은 직접 처리한다. 독립적인 실질 작업만 병렬 위임한다.
- 역할 설정은 .codex/agents/에 있다. 사용 가능한 커스텀 에이전트를 호출한다. 호출 도구가 커스텀 역할을 지원하지 않으면 해당 파일을 읽고 역할 지침과 모델을 명시해 위임한다. 모델을 바꿔 위임할 때는 필요한 문맥을 요약해서 전달한다.
- 위임 기능이나 지정 모델이 없으면 그 제한을 알리고 가능한 작업을 직접 진행한다. 모델이 적용되었다고 추측하지 않는다.

## 역할 배정
- research_planner: 가설, 문헌 검토, 실험설계, 평가 지표, 통계 및 연구계획. gpt-6-astra / medium.
- experiment_engineer: 실험 코드, 데이터 처리, 테스트, 재현 가능한 실행과 결과 정리. gpt-6-astra / low.
- presentation_builder: 문서 작성, 발표 구성, 근거가 연결된 그래프, PPTX 및 발표 노트. gpt-6-astra / low.
- 실험의 타당성 또는 어려운 오류가 해결되지 않으면 총괄이 검토하고, 필요한 부분만 Astra로 재검토한다.
- 담당자는 추가 위임하지 않는다. 총괄이 최대 3명의 담당자와 작업 순서를 관리한다.

## 인계와 파일 관리
- 시작 시 orchestration/STATUS.md와 관련 원본을 읽는다. STATUS가 원본보다 오래되면 원본을 확인하여 정정한다.
- 기존 폴더 구조를 유지한다. 이름에 '이전', '아카이브'가 있는 자료를 현재 계획으로 자동 채택하지 않는다.
- 연구설계 → 실험 명세 → 구현 → 실행 → 결과 검증 → 발표 순서로 진행한다. 연구계획 발표는 실제 결과 없이도 만들 수 있다.
- 위임할 때 입력 파일, 출력 파일, 수정 가능한 범위, 완료 기준을 명시한다. 같은 파일에 여러 담당자가 동시에 쓰지 않는다.
- 각 담당자는 작업 결과, 수정 파일, 검증 내용, 미해결 사항을 반환한다. STATUS.md와 DECISIONS.md는 총괄만 갱신한다.
- 실험별로 orchestration/templates/EXPERIMENT.md를 복사해 명세와 실행 기록을 남긴다. 관련 코드·원본 데이터·결과 경로를 연결한다.
- 원본 측정 데이터와 과거 실행 결과는 덮어쓰지 않는다. 실행별 고유 폴더를 사용한다.

## 검증 기준
- 코드 작성, 테스트 통과, 실제 실험 실행, 결과 검증을 별개 상태로 기록한다.
- 실행하지 않은 실험과 생성한 예시 데이터를 실제 관측 결과로 표현하지 않는다.
- 논문과 수치의 출처를 확인하고, 연구 가설·예상·관측·해석을 구분한다.
- 실험 변경 시 데이터 누수, 비교 조건, 단위, 표본 수, 결측 처리와 평가 지표의 일관성을 검토한다.
- 테스트는 변경에 필요한 수준으로 수행한다. 카메라·장비·참가자가 필요한 실제 측정을 테스트로 대체했다고 주장하지 않는다.
- 발표 수치와 그림마다 원본 결과를 연결한다. 근거가 없으면 미측정 또는 예정으로 표시한다.
- 문서·PPT 제작 시 사용 가능한 해당 제작 스킬을 사용하고 렌더링으로 검수한다. 스킬이 없으면 가능한 검수와 제한을 보고한다.
