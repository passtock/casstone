## 2. 왜 스레드인가 (실측 근거)

| 항목 | 실측 |
|---|---|
| Pose(model_complexity=1) 1프레임 | **≈ 29 ms** (34 fps) |
| Pose(model_complexity=0, Lite) 1프레임 | ≈ 22 ms (45 fps) |
| Hands 1프레임(앱 기존) | ≈ 15 ms |

같은 루프에서 순차 실행하면 30 fps 카메라가 **약 22 fps** 로 떨어진다. 그래서 Pose를 **워커 스레드**로 돌리고 캡처 루프는 큐에 넣기만 한다.

**큐가 포화되면 조용히 사라지지 않는다.**

```
n_submitted = n_processed + n_failed + n_dropped_by_queue     ← 불변식, stats()/meta.json 에 기록
```
작은 큐(2)에 200프레임을 밀어넣은 오라클 시험에서 `proc=2 drop=198 submitted=200` → **합계 보존 확인**. 드롭이 50건 단위로 콘솔에 찍힌다.

## 4. 붙이면 무엇이 생기는가

촬영을 시작하면 세션 폴더에 두 가지가 추가된다. **기존 파일·스키마는 그대로**다.

```
<세션 폴더>/
├── original.avi / mediapipe.avi / video_timestamps.csv     ← 기존 그대로
├── raw_rgbd/<frame_id>.npz                                 ← 기존 그대로
├── Session_..._landmarks.csv                                ← 기존 그대로 (Hands 21점)
├── raw_pose/<frame_id>.npz                                  ← 신규 (프레임별 원자 저장)
├── pose_landmarks.csv                                       ← 신규 (Pose 33점 롱포맷)
└── pose_landmarks.meta.json                                 ← 신규 (출처·계수·드롭·좌표 경고)
```

**`pose_landmarks.csv` 헤더** (= `experiments/v11/pose_offline.py` 와 동일 → 기존 오프라인 도구가 수정 없이 읽는다):
```
Frame_ID, time_s, Landmark_ID, visibility, MP_X_m, MP_Y_m, MP_Z_m, RS_X_m, RS_Y_m, RS_Z_m, RS_Status
```

- `MP_*` = world landmark(미터, **원점 = 골반 중점**)
- `RS_*` = 카메라 좌표. 정렬 depth + 내부파라미터가 있으면 `ok`, 없으면 `no_depth`(빈칸)
- `RS_Status` 어휘는 앱과 맞췄다: `ok` · `no_depth` · `depth_hole` · `depth_out_of_range` · `insufficient_depth` · `no_intrinsics` · `deprojection_failed` · `not_detected`

⚠️ **좌표계 경고(실측):** world landmark 원점은 양 골반 중점이다(파일럿에서 `hips mid ≈ (−0.0001, −0.0011, 0.0004) m` 확인).
→ world landmark로는 **체간의 전역 이동이 복원되지 않는다.** 골반 기준 **상체 기울기**만 남는다.
→ 전역 이동이 필요하면 `RS_*`(정렬 depth + 내부파라미터)를 써야 한다. `pose_recorder.py` 는 앱이 이미 미터로 들고 있는 `self.latest_depth` 를 `depth_m=` 로 받아 그대로 역투영한다(중복 변환 없음).

## 7. 주의사항
1. **프레임레이트:** Pose는 워커 스레드지만 CPU를 쓴다. Hands와 동시 실행 시 실효 fps가 떨어질 수 있다. 부족하면 `PoseRecorder(folder, model_complexity=0)` 로 Lite를 쓰거나, 패치 호출을 `if self.frame_id % 2 == 0:` 로 감싼다(어디를 고치면 되는지는 패처 diff의 ②번 줄).
2. **드롭은 숨기지 않는다.** `meta.json` 의 `n_dropped_by_queue` 를 본다. 0이 아니면 그만큼 Frame_ID 구간이 비고, v11의 `qrobust` 가 `missing_frames`/`gap_ratio_exceeded` 로 검출한다.
3. **되돌리기:** 위 §상단의 `copy` 한 줄. 백업은 `.bak_20261001_184009`.
4. **기존 앱 동작 불변.** Pose는 읽기만 한다(프레임을 복사해 넘김). 표시·미러링·기존 CSV에 영향 없다.
4. **import 실패 시:** 앱을 그 폴더에서 실행해야 `pose_recorder` 가 잡힌다. 실행 위치가 다르면 `[POSE] pose_recorder 를 불러오지 못했습니다` 가 뜨고 앱은 정상 동작한다.
5. **앱이 업데이트되면:** 앵커가 바뀌어 패처가 **중단**한다(조용히 잘못 넣지 않는다). 그때는 3곳을 다시 확인한다.
