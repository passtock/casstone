# 두 방법 동시 측정·저장

## 2026-09-08 지연·저장 종료 처리 변경

추가 종료 방지 처리: 일시적인 RealSense·웹캠 수신 중단은 창이나 세션을 닫는 대신 수신 대기 상태로 전환합니다.
다시 수신되면 이어서 기록하며, 수신되지 않은 시간은 실제 공백으로 남깁니다. 화면 콜백의 Python 예외는
창을 유지하고 현재 데이터를 부분 저장하도록 처리합니다. 실행별 진단 기록은 `outputs/logs/runtime_*.log`,
네이티브 충돌 진단은 `outputs/logs/crash_*.log`에 남습니다. 네이티브 충돌 자체를 복구하는 기능은 아닙니다.

- 전체화면 실행은 유지합니다. 왼쪽 아래의 측정 버튼을 줄이고 그 아래에 실시간 기록 확인 창을 추가했습니다.
- `저장 / 수신 / 대기`는 각각 파일 쓰기가 끝난 원본 수, 저장기에 전달한 원본 수, 아직 쓰기를 마치지 않은 원본 수입니다. 전원 차단에 대비한 디스크 동기화 완료 표시와는 다릅니다.
- 오른손·왼손별 MP 파지폭(mm), RS 파지폭(mm), 유효한 깊이 관절 수(21개 중), 검지 PIP 내각(°)을 표시합니다. `--`는 결측이며, PIP는 완전 폄이 약 180°인 내각입니다.
- 화면은 100ms 간격으로 최신 영상만 가져옵니다. 측정값과 원본 저장은 이 표시 주기와 별개로 유지합니다. 그래프와 3D는 현재 탭만 최대 2Hz로 갱신합니다.
- 영상의 시간 공백을 채울 때 이미 압축한 JPEG를 재사용합니다. 원본 NPZ는 배열을 압축 없이 무손실 저장해 깊이 압축에 걸리던 CPU 작업을 줄였습니다. 그만큼 깊이 파일 용량은 이전보다 커집니다.
- 저장 대기열은 8장으로 제한합니다. 대기열이 차면 **다음 프레임을 받기 전에 촬영을 잠시 늦추며**, 이미 받은 프레임을 임의로 버리지 않습니다. 센서 설정 FPS와 실제 처리 FPS는 다를 수 있습니다.
- `종료 및 저장`을 누르면 원본·영상 마무리, CSV·그래프 내보내기를 백그라운드에서 처리합니다. 저장 중에도 미리보기는 유지하고, 완료되면 다음 세션을 시작할 수 있습니다.
- 디스크 공간 부족 등 실제 쓰기 오류는 부분 저장으로 표시합니다. 저장 오류가 카메라 작업까지 종료시키지 않도록 분리했습니다.
- 큰 영상은 두 AVI를 동시에 약 1GiB 단위로 나눕니다. 첫 파일 이름은 그대로이고, 이후 `original_part002.avi` / `mediapipe_part002.avi` 등이 이어집니다. 메타데이터 `raw_recording.videos.parts`에 각 파일의 시작 위치와 프레임 수를 기록합니다.

이번 변경 후 추가 실행 테스트는 사용자 요청에 따라 진행하지 않았습니다.

`Mirror_therapy.py`를 기존처럼 실행하고 **전체 세션 시작 → 구간 측정 → 세션 종료 및 저장**을 사용합니다.
프로그램은 바로 전체화면으로 열립니다. **F11**로 전체화면/창 모드를 전환하고, **Esc**는 녹화를 끝내지 않고 창 모드로 돌아갑니다.
종료는 **Q** 또는 화면의 종료 버튼을 사용합니다. 상단 옵션은 여러 줄로 배치하고,
왼쪽 설정만 스크롤되도록 하여 측정 버튼이 항상 보이게 했습니다. 그래프·3D·회차 결과는 오른쪽 탭에서 선택합니다.
RealSense가 연결되어 있으면 두 방법을 동시에 계산합니다. 웹캠으로 동작하면 MediaPipe 결과만 나오며 RealSense 값은 빈 칸입니다.

- **MP**: MediaPipe 원본 world landmark의 엄지끝(4)–검지끝(8) 거리. 모델 추정값입니다.
- **MP_cal**: 위 거리에 실측 손목–중지 MCP 길이 보정을 적용한 별도 값입니다.
- **RS**: 같은 컬러 프레임의 MediaPipe 픽셀 위치에 대응하는 RealSense 깊이를 사용한 3D 거리입니다.
- **RS_minus_MP**: 두 방법 사이의 차이입니다. 실측 기준에 대한 정확도 오차가 아닙니다.

영상에는 `MP …mm | RS …mm`가 함께 표시됩니다. 기존 관절각·게이지·TAM·3D 골격은 MediaPipe 계열입니다.
이번 변경에서 RealSense를 이용한 관절각까지 추가하거나 검증하지는 않았습니다.

## 저장 위치와 파일

스크립트 옆 `outputs/데이터_저장/피험자/Session_날짜_시각_마이크로초_고유ID/`에 세션별 새 폴더를 만듭니다.

| 파일 | 내용 |
|---|---|
| `original.avi` | 표시·반전 없는 원본 카메라 컬러 영상의 재생용 파일 |
| `mediapipe.avi` | 동일 프레임에 손 랜드마크·거리·프레임 번호를 표시한 영상 |
| `*_distance_comparison.csv` | 같은 프레임·같은 손의 MP/MP_cal/RS 거리(mm), 유효 여부, 손끝 깊이 결측 사유, 센서 프레임 번호·시각 |
| `*_landmarks.csv` | 21개 랜드마크 각각의 원본 픽셀, MP XYZ(m), RS XYZ(m), 깊이·유효성 |
| `*_frame_quality.csv` | 손이 없던 프레임도 포함한 인식 여부·과제 조건 충족 여부 |
| `*_continuous_raw.csv` | 기존 각도·필터·정준좌표 기록과 프레임 번호 |
| `*_trials_summary.csv` | 회차별 기존 지표, 유효 측정 시간, RS 유효 표본 수, 두 방법의 최대 거리와 차이 요약 |
| `subject_metadata.json` | 해당 세션의 설정, 카메라 내부·외부 파라미터, 버전, 코드 해시, 원본 저장 결과·오류 |
| `raw_frames/frames.csv` | 원본 파일과 프레임 번호·호스트/센서 시각 대응표 |
| `raw_frames/frame_XXXXXXXX.npz` | 덧그림·미러링 전 컬러 배열, 원본 깊이, 컬러에 정렬한 깊이를 무손실 저장 |

각 CSV의 `Frame_ID` 또는 `frame_id`로 대응시킵니다. NPZ는 다음 배열을 포함합니다.

- `color_bgr`: `uint8`, OpenCV의 **BGR** 채널 순서입니다.
- `depth_native_z16`: `uint16`, 원래 깊이 해상도입니다. 깊이가 없는 프레임에는 키가 없습니다.
- `depth_aligned_z16`: `uint16`, 컬러에 정렬한 깊이입니다. 깊이가 없는 프레임에는 키가 없습니다.
- `metadata_json`: 깊이 스케일, 내부·외부 파라미터, 프레임 번호와 시각을 담은 JSON 문자열입니다.

두 AVI는 **세션 시작부터 종료까지** 같은 크기·같은 프레임 순서로 저장합니다. 손이 인식되지 않은 구간도 포함합니다.
화면이 Depth 모드여도 MediaPipe 컬러 영상은 계속 저장되며, 화면 미러링은 두 저장 영상의 방향을 바꾸지 않습니다.
AVI는 호환성을 위한 MJPG 압축 재생본이고 픽셀 단위 원본은 NPZ에 무손실로 보존합니다.
재생 속도는 30 FPS이며, 촬영 프레임 간 시간 공백은 이전 화면을 반복하여 유지합니다.
`raw_frames/frames.csv`의 `video_frame_index`는 전체 영상 기준 **0부터 시작하는 프레임 번호**입니다.
분할된 경우 `video_part`(1부터 시작)와 `video_part_frame_index`(0부터 시작)로 해당 AVI 안의 위치를 찾습니다.
정확한 연구용 시각은 원본 타임스탬프를 사용합니다. 저장이 끝나면 두 AVI의 프레임 수와 처음·마지막 프레임을 다시 읽어 검사합니다.
검증 전/실패한 파일은 `.partial.avi`로 남고 정상 완료 시 위 이름으로 바뀝니다.

깊이의 m 값은 `z16 * depth_scale_m`입니다. 0은 유효한 거리로 사용하지 않습니다.
아래처럼 설치된 NumPy로 다시 열 수 있습니다.

```python
import json
import numpy as np

with np.load("raw_frames/frame_00000123.npz", allow_pickle=False) as frame:
    bgr = frame["color_bgr"]
    metadata = json.loads(frame["metadata_json"].item())
    if "depth_aligned_z16" in frame:
        depth_m = frame["depth_aligned_z16"].astype(float) * metadata["depth_scale_m"]
```

## 좌표·결측·시간 해석

MP의 원점은 손 중심이고 RS의 원점은 정렬된 카메라 좌표계입니다. 두 XYZ를 그대로 빼서 위치 오차라고 해석하면 안 됩니다.
양쪽 모두 원본 비반전 영상을 기준으로 계산하므로 표시 미러링을 켜도 저장 픽셀·좌표·좌우 손의 뜻은 바뀌지 않습니다.

RS는 손끝 중심 픽셀의 깊이를 사용합니다. 화면 밖, 깊이 0, 0.10–2.00m 범위 밖, 3×3 이웃 유효 표본 부족,
이웃 깊이의 90–10백분위 차이 30mm 초과는 결측으로 남깁니다. 이 기준은 개발용 기본값이며 실제 카메라·손 자세에서 검증해야 합니다.
배경과 섞인 손끝 경계는 `depth_edge`로 제외될 수 있습니다. 0mm 파지폭은 두 점이 모두 유효하면 정상값으로 저장합니다.
결측 RS 값을 MP 값으로 대체하거나 이전 프레임 값으로 채우지 않습니다.

자동 회차 시간은 시작 시 인식된 손이 계속 인식되는 연속 프레임 간격만 합산합니다. Task 4는 양손이 필요합니다.
프레임 수신 중단·손 인식 실패는 카운트다운을 멈춥니다. `Duration_s`는 실제 경과 시간,
`Valid_Duration_s`는 해당 손의 연속 유효 구간 길이입니다. RS 깊이 유효율은 별도로 보고하므로 자동 5초가 RS 유효 깊이 5초를 보장하지는 않습니다.
누락 프레임 또는 0.25초보다 긴 공백을 가로질러 사이클·속도를 계산하지 않습니다.

`capture_monotonic_s`는 프로그램이 프레임을 수신한 호스트 시각이고, 센서 노출 시각과 같지 않습니다.
센서 시각·시각 도메인은 별도로 저장합니다. 원본 저장 대상은 프로그램이 수신한 모든 세션 프레임이며,
카메라 자체가 생성한 모든 프레임을 보장하는 녹화기는 아닙니다. 종료 요청과 동시에 수신 중이던 원본이 조금 더 저장될 수 있으므로
정확한 분석 범위는 메타데이터의 세션 길이와 프레임 시각으로 제한합니다.

## 저장 실패와 검증 범위

원본 저장은 별도 스레드의 제한된 큐로 수행합니다. 일시적으로 디스크가 느리면 촬영 속도를 조절합니다.
공간 부족 등 실제 쓰기가 실패하면 해당 세션의 기록을 중단하고
부분 저장 상태와 오류를 표시합니다. 완료 시 메타데이터의 `raw_recording.complete`와 `session_error`를 확인할 수 있습니다.
요약 파일 저장 실패 시 메모리 기록을 유지하고 **저장 재시도** 버튼을 표시합니다. 저장 중에는 종료를 기다립니다.
원본 컬러·깊이는 일반 동영상보다 저장 공간을 많이 사용합니다.

개발 환경에서는 합성 거리·깊이 결측·반복 검출·자동 시간·저장/재읽기·저장 실패를 자동 검사합니다.
실제 RealSense 거리 정확도, 촬영 FPS, 손끝 가림과 깊이 품질은 장치 연결 후 실측 비교가 필요합니다.
기존 `SPARC` 열은 고정 10Hz 스펙트럼 지표를 유지한 것으로, 임상 SPARC 구현을 검증한 값으로 해석하지 않습니다.

## 의존성

기존에 실행하던 Python 환경을 사용하세요. 새 환경에는 `requirements.txt`를 설치하고,
RealSense를 사용할 환경에는 `requirements-realsense.txt`를 설치합니다.
카메라를 열지 않는 회귀 검사는 이 폴더에서 다음 명령으로 실행합니다.

```text
python -B -m unittest test_mirror_therapy -v
```

좌표 변환은 [RealSense 공식 투영 문서](https://dev.realsenseai.com/docs/projection-in-realsense-sdk-2-0/)의
픽셀·깊이·카메라 내부 파라미터를 통한 3D 복원 방식에 따릅니다.
