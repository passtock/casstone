## 1. 처음에는 무엇을 하려고 했나 (2026년 8월)

처음 계획서(2026.08.28)는 **욕심이 컸습니다.**

- **장비:** 공압 로봇 장갑(손을 펴고 쥐어주는 장치) + 카메라(RealSense) + 웹캠
- **과제 3개:** ① 맨손 쥐었다 펴기 ② 5cm 원통 잡기 ③ 7cm 공 잡기
- **숫자:** 손가락 관절 각도 15개, 손 벌림(MGA), 부드러움(SPARC) 등
- **AI 2단계:** 1단계는 예전 방식 AI(CNN+LSTM)가 점수를 추정, 2단계는 채팅형 AI(Med-Flamingo 같은 의료용)가 **소견서**를 씀
- **목표:** 10월엔 논문, 12월엔 캡스톤 완성

**비유하자면:** "집을 짓고, 가구도 만들고, 정원도 꾸미자"고 한 것과 같습니다. 그런데 **남은 시간이 10주**뿐이었습니다.

그래서 하나씩 덜어냈습니다. 로봇 장갑은 별도 과제로 미루고, **"카메라로 손을 보고 AI가 점수를 매길 수 있나"** 라는 한 가지 질문에 집중하기로 했습니다.

## 2. 왜 방향을 바꿨나 — "이미 남이 한 것"과 "우리만 할 수 있는 것"

### 2-1. 제일 아팠던 순간 (9월 23일)

처음엔 "아무도 안 한 연구"라고 생각했습니다. 그런데 논문을 **체계적으로 뒤져보니**, 우리가 "비어 있다"고 한 3가지가 **전부 이미 있었습니다.**

| 우리가 한 말 | 실제로는 |
|---|---|
| "카메라로 손가락까지 검증한 사람이 없다" | **Amprimo 2024** 가 이미 했다 |
| "화질 품질 규칙(게이팅)은 없다" | **EVGS 2025** 등이 이미 했다 |
| "가림(가려짐) 실패를 정량화한 사람이 없다" | **Hand Visibility Detector** 가 이미 했다 |

특히 아팠던 건, 그중 하나(**Amprimo 2024**)가 **사용자(이재용) 메모에 이미 적혀 있던 논문**이었다는 점입니다. "내가 다시 안 읽고 '빈 곳'이라고 썼다"는 걸 인정하고 기록했습니다.

### 2-2. 그래서 살아남은 것 (우리 자리)

무작정 "우리가 처음이다"라고 하면 안 되니, **진짜 비어 있는 것만** 남겼습니다. 그게 **"여러 조건을 똑같이 두고, 숫자를 줬을 때/안 줬을 때/품질 나쁜 숫자를 뺐을 때 점수가 어떻게 달라지는가"** 를 **처음으로 측정**하는 일입니다.

표현을 이렇게 고정했습니다: **"우리가 처음 만든 게 아니라, 처음 측정한다."**

### 2-3. 나머지 방향 전환

- **ARAT 2개 과제**(블록 3번, 구슬 12번)로 시작 → 나중에 3개로 늘림(교수님 피드백)
- **"손가락 벌림을 영상만 보고 맞힐 수 있다"** 는 주장은 버림. 다른 논문(**Li 2022**)이 카메라로 손목 위치를 재면 **평균 9.6cm나 틀렸다**고 보고했고, 우리가 보려는 **구슬은 1.6cm**밖에 안 됩니다. 즉 **원리적으로 불가능**에 가깝습니다.

## 3. 실수를 찾아 고친 큰 사건들

### 3-1. 없는 논문을 인용하고 있었다 (9월 25일)

우리 문서에 넣은 논문 출처(DOI)를 **전부 자동으로 검사**했습니다. 결과:

- **증거맵 2종·계획서는 깨진 인용 0건** ✅
- 그런데 **캡스톤 분석보고서 5개에는 25건의 문제**가 있었습니다. 그중 **8건은 "링크는 열리는데 전혀 다른 논문"** 이었습니다.
  - 예: "손 정밀도 논문"으로 적은 링크가 **차량용 토양 측정기** 논문이었고, "PREP2 논문"은 **알츠하이머 뇌네트워크** 논문이었습니다.
- **무서운 점:** 링크를 눌러도 열려서 **눈으로는 안 보입니다.**

**고친 방법:** 실존하는 올바른 논문으로 16건 교체, 10건은 "미검증" 딱지를 붙여 보존(억지로 안 만듦). **"캡스톤 보고서 5개는 외부에 내보내지 말 것"** 이라고 기록했습니다.

### 3-2. 시계가 고장 나 있었다 (9월 25일 ~ 9월 28일)

이건 하마터면 **결론을 통째로 잘못 잡을 뻔한** 사건입니다.

- 데이터에 **손이 초당 7.9m(시속 28km)로 움직였다**는 값이 있었습니다. 사람 손은 그렇게 빠르지 않습니다(정상 초당 0.3~0.8m).
- 원인을 파보니 **운동이 아니라 시계 오류**였습니다.
  - 컴퓨터가 **벽시계**로 시간을 재는데, 같은 순간이 여러 번 찍혀서 **시간 간격이 1/34로 줄어들었고**, 그 상태로 속도를 계산하니 값이 **10억 배**로 폭발한 것입니다.
  - **프레임 시계**로 다시 계산하니 **0.605m/s** (정상)로 돌아왔습니다.
- 이 과정에서 **내(파인만) 결론을 3번 뒤집었습니다.** "P95는 안정적이다", "화면 렉 때문이다", "SPARC가 통과한다"고 했다가, 검증 결과 **전부 틀렸음**을 인정하고 철회했습니다.
  - 예: "SPARC 통과"는 손을 **좌우로 나눠보니 오른손이 기준 초과**였는데, **양손을 평균 내서 가려졌던 것**입니다.

**배운 교훈 3가지:**
1. **최댓값(peak)은 못 믿는다. 대신 P95(상위 5%)를 쓴다.**
2. **시계를 먼저 정해야** 품질 판정을 할 수 있다.
3. AI가 만든 분석도 **"내가 틀렸다"를 반복**할 수 있으니 계속 검증해야 한다.

### 3-3. 코드가 계획과 **다른 실험**을 하고 있었다

계획서에는 "K1·K2 두 숫자"를 쓴다고 썼는데, **실제 코드는 4개를 쓰고 과제도 달랐습니다.** 문서와 코드가 다르면, 촬영 후 "무엇을 넣었는지" 재구성할 수 없습니다. → **문서와 코드를 1:1로 맞추는 것**을 원칙으로 세웠습니다.

### 3-4. 말 바꾸기 (9월 25일, 사용자 지시)

"건강인" → **"비장애인"**, "환자" → **"장애인"** 으로 문서 80여 개를 고쳤습니다. 이때 **데이터 폴더 이름 같은 건 실수로 바꾸면 안 되므로** 5곳은 원래대로 보존했습니다.

## 4. 교수님 질문이 바꾼 것 (10월 1일)

교수님이 두 가지를 물으셨습니다.

> (1) **왜 ARAT 2개 과제만 하냐? 그걸로 충분하냐?**
> (2) **손 움직임만 보는 게 맞냐? 상체를 봐야 하지 않냐?**

### 4-1. 가장 중요한 발견 — "체간(몸통)은 원래 채점 기준이었다"

교수님 질문을 검증하다가 **ARAT 공식 채점표 원문**(Yozbatiran 2008)에서 이런 문장을 찾았습니다:

> *"몸통이 의자 등받이에서 완전히 떨어지면 → 2점."*

즉 **몸통은 우리가 "추가로 넣고 싶은 지표"가 아니라, ARAT 규칙이 이미 요구하는 정보**였습니다. 그런데 우리 계획은 **몸통을 카메라로 보이게 하지도, AI에 알려주지도 않았습니다.** → 교수님 질문은 "범위를 늘려달라"가 아니라 **"채점 근거 하나가 빠져 있다"** 는 지적이었습니다.

### 4-2. 그래서 바뀐 것
- 과제 **2개 → 3개** (블록, 구슬, **손바닥 머리 위에 대기**)
- **몸통(체간) 변위**를 숫자에 추가
- 촬영 앱에 **몸통 인식(Pose)** 기능을 새로 넣음 (원본 앱은 안 건드리고 새 모듈만 추가)

## 5. 지금 계획 (v13.2) — 쉬운 말로

**한 문장:** "같은 환자의 같은 영상에 대해, ⓐ 영상만 / ⓑ 영상+숫자 / ⓒ 영상+품질 좋은 숫자만 / ⓓ 영상+아무 숫자나 같은 개수 를 각각 주고, 치료사 점수와 가장 잘 맞는 게 무엇인지 본다."

| 항목 | 내용 |
|---|---|
| **과제** | ① ARAT 3번(블록 5cm·55g) ② ARAT 12번(구슬 1.6cm·5.4g) ③ 손바닥 머리 위에 대기 |
| **사람** | 장애인 25명 + 비장애인 25명(참고용) + 랩실 점검 6명 |
| **한 사람당** | 3과제 × 3회 = 9시행 |
| **카메라** | RealSense **D455 1대** (손·팔·몸통·머리 위·물건이 다 보이게) |
| **숫자 4개** | 손 벌림, 손가락 굽힘 합, 손목 부드러움(SPARC), 몸통 변위 |
| **AI 모델** | Qwen2.5-VL-32B (주), 비교용 4개 |
| **주 질문 3개** | ① 숫자를 주면 좋아지나 ② 품질 나쁜 건 빼면 좋아지나 ③ 그냥 개수만 맞춰 빼는 것과 뭐가 다른가 |
| **기간·예산** | 10주, 공식 15만원 + 사비 상한 15만원, RTX 5090 |

**중요:** 이 실험은 **"점수를 새로 만드는 것"이 아니라 "치료사 점수를 AI가 더 잘 따라가는지"** 를 보는 것입니다.

## 6. 카메라 하나로 무엇을 믿을 수 있나 (쉬운 결정표)

가장 자주 나오는 질문: **"카메라 하나로 어떻게 품질을 아느냐?"**
답: **알 수 없습니다. 그래서 "정확도"가 아니라 "믿을 만한가"를 잽니다.**

| 무엇을 | 믿을 수 있나 | 이유 |
|---|---|---|
| 팔꿈치·어깨 각도 | **믿을 만함** | 다른 연구에서 ICC 0.92~0.94 (거의 완벽에 가까움) |
| 동작 시간 | **믿을 만함** | ICC 0.76 |
| 몸통이 앞으로 나온 거리 | **조건부** | ICC 0.93이지만, **몸통 중심이 기준이라 "이동 거리"는 원래 못 잡음** → 정지 2초 기준선을 꼭 찍어야 함 |
| 몸통 회전 | **못 믿음** | ICC 0.38 (낮음) |
| 손목 순간 속도(최고속도) | **못 믿음** | ICC 0.21 (사실상 실패) |
| 속도 봉우리 개수 | **못 믿음** | ICC 0.38 |
| 부드러움(SPARC) | **아직 모름** | 지금까지 **아무도 카메라로 검증한 적 없음** → **우리가 처음 시도** |
| 손가락 벌림(구슬) | **원리적으로 어려움** | 카메라 손목 오차 9.6cm vs 구슬 1.6cm |

**비유:** 카메라는 "큰 움직임(팔 각도, 시간, 몸통 위치)"은 잘 보지만, **"빠르고 미세한 움직임(손목 속도, 부드러움)"은 잘 못 봅니다.** 그래서 우리는 **부드러움(SPARC)을 정면으로 도전**하는 것이고, 그게 이 연구의 핵심 기여입니다.

### ✅ 확인된 것 (증거 있음)
- ARAT 채점 기준·물성(블록 55g, 구슬 5.4g, 선반 37cm, 3점=5초 이내) — 원문 확인

- 문헌 48건의 논문 번호(PMID/DOI) **전부 실제 존재** (2026-10-05 재검증, 48/48)
- 우리 앱·코드의 계산이 계획과 일치하는지 (오라클 검사 통과)

### ❌ 아직 안 된 것 (정직하게)
- **실제 환자 데이터 0명** — 있는 건 비장애인 1명의 옛 데이터(ARAT 아님)뿐
- **AI(VLM) 실제 실행 0회** — 컴퓨터(GPU) 경로가 아직 안 정해짐
- **실제 D455 카메라로 촬영 0회**
- 카메라 거리·각도 같은 중요한 값이 **일부 선행논문에도 안 적혀 있음**

6. **실물 파일럿 촬영** — 3D프린트 선반(37cm) + D455 + 진짜 ARAT 1회

## 10. 어려운 말 사전

| 말 | 쉬운 뜻 |
|---|---|
| **ARAT** | 손 기능 검사. 19개 항목, 0~3점. 우리는 3번(블록)·12번(구슬) 사용 |
| **FMA-UE** | 상지 운동 기능 검사(0~66점) |
| **VLM** | 영상+글을 같이 이해하는 AI (예: Qwen2.5-VL) |
| **운동학(kinematics)** | "어떻게 움직였나"를 숫자로 표현한 것 (각도·속도·부드러움) |
| **SPARC** | 움직임이 얼마나 **부드러운지** 재는 점수 (0에 가까울수록 매끄러움) |
| **MGA** | 최대 손 벌림 |
| **ICC** | 두 측정이 얼마나 일치하는지 (1에 가까울수록 좋음, 0.75 넘으면 좋음) |
| **MDC** | "믿을 만한 최소 변화량". 이보다 작은 변화는 측정오차로 봄 |
| **게이팅(gating)** | 품질이 나쁜 데이터를 **걸러내는 것** |
| **보류(abstention)** | 확신이 없으면 **판단을 안 하고 넘기는 것** |
| **GMM** | 움직임 패턴을 **여러 무리로 나누는** 통계 방법 |
| **체간(trunk)** | 몸통. ARAT에서 **등받이에서 떨어지면 감점** |
| **오라클(oracle)** | "정답을 아는 합성 데이터"로 코드가 맞는지 확인하는 검사 |
| **평탄화(flatlining)** | AI가 누구에게나 비슷한 점수를 주는 현상 |
