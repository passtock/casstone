## 1. 처음에는 무엇을 하려고 했나 (2026년 8월)

처음 계획서(2026.08.28)는 **욕심이 컸습니다.**

- **장비:** 공압 로봇 장갑(손을 펴고 쥐어주는 장치) + 카메라(RealSense) + 웹캠
- **과제 3개:** ① 맨손 쥐었다 펴기 ② 5cm 원통 잡기 ③ 7cm 공 잡기
- **숫자:** 손가락 관절 각도 15개, 손 벌림(MGA), 부드러움(SPARC) 등
- **AI 2단계:** 1단계는 예전 방식 AI(CNN+LSTM)가 점수를 추정, 2단계는 채팅형 AI(Med-Flamingo 같은 의료용)가 **소견서**를 씀
- **목표:** 10월엔 논문, 12월엔 캡스톤 완성

**비유하자면:** "집을 짓고, 가구도 만들고, 정원도 꾸미자"고 한 것과 같습니다. 그런데 **남은 시간이 10주**뿐이었습니다.

그래서 하나씩 덜어냈습니다. 로봇 장갑은 별도 과제로 미루고, **"카메라로 손을 보고 AI가 점수를 매길 수 있나"** 라는 한 가지 질문에 집중하기로 했습니다.

### 1-1. 잠깐, 원래는 "FMA-UE + 4개 과제"였습니다 (중요)

이재용 님이 "우리 원래 FMA 4과제로 하기로 했었잖아"라고 하셔서 **대화기록과 옛 계획서를 전부 뒤져봤습니다. 맞습니다.** 처음 계획은 **FMA-UE를 재고, 과제가 4개**였습니다.

**원래 4개 과제:**
1. **맨손** 쥐었다 펴기 (물체 없음) — 손가락이 서로 붙어 같이 움직이는지(연합반응) 보기 위함
2. **5cm 원통** 잡기 — 캔·컵 같은 일상 파지
3. **7cm 공** 잡기 — 엄지 대립(맞섬), 손 벌림 조절
4. **공압 로봇 장갑 미러테라피** (치료 15분) — 건손이 움직이면 마비손 장갑이 따라 움직임

**왜 이 구조였나:** "FMA-UE 손 7개 항목 + ARAT 파지 영역을 100% 대변"하려고. 그리고 **브룬스트롬 단계와 1:1로 맞췄습니다** — 1번=3단계, 2번=4단계, 3번=5단계, 4번=치료.

**당시 30분 세션 흐름:** 수기 FMA+각도계(5분) → 컴퓨터 평가 1~3번(5분) → 미러테라피 치료(15분) → 다시 평가 1~3번(5분)

**장비도 더 많았습니다:** 공압 로봇 장갑 + 공기펌프/밸브 제어보드(반응 70ms 이내) + 카메라 + 웹캠까지.

**그런데 왜 바꿨나?**
- **FMA → ARAT:** 카메라로 FMA 자동채점은 **이미 임상검증까지 끝난 분야**(Brain Sci 2022, Clin Rehabil 2024). 우리가 또 하면 "새롭지 않음". 그래서 FMA/ARAT는 **정답(치료사 점수)** 으로 쓰고, AI가 그 정답에 얼마나 가까워지는지를 봅니다. **"ARAT가 FMA보다 우수해서"가 절대 아닙니다.**
- **4개 → 2개:** 카메라 숫자가 임상점수를 잘 맞히는 구간은 "**했냐/못했냐**"(정확도 0.96~0.99)이고 "**2점이냐 3점이냐**"는 낮습니다(0.70~0.84). 그래서 블록·구슬만 남겼습니다.
- **GMM 제외:** 정상인 몇 명으로 "정상 무리"를 만들면 무리가 마음대로 흔들려서 뺐습니다.

**그리고 나중에(10월 1일) 교수님 질문으로 다시 3개로 늘렸습니다**(블록 · 구슬 · 손바닥 머리 위에 대기).

> **정리: 4개(FMA-UE) → 2개(ARAT) → 3개(현재).**
> 참고로 교수님께 받은 질문 중에 **"원래 FMA-UE를 하고 4개 과제를 하기로 했는데 왜 바꿨나"** 라는 질문이 **이미 예상질문 목록에 들어 있었습니다**(교수면담 준비 문서).

### 1-2. 그때 자세히 — 장비·과제·숫자·AI (쉬운 말로 최대한)

이재용 님이 궁금해하실 것 같아, 원래 계획을 **장비·과제·숫자·AI·통계**로 나눠 아주 자세히 풀었습니다. (옛 계획서 원문에서 그대로 가져왔습니다.)

#### (1) 그때 쓴 장비 — 지금보다 훨씬 많았습니다
| 무엇 | 사양 | 하는 일 |
|---|---|---|
| 카메라 | **RealSense D435** 또는 1080p 웹캠(60fps) | 손 영상 + 깊이(3D) |
| 손 인식 | **MediaPipe Hand Landmarker** + SVD 손바닥 정준화 | 손 관절 21개를 3D로 뽑고, 카메라 각도·손 크기에 상관없게 정리 |
| 필터 | One-Euro + Occlusion Hold | 손 떨림 제거, 물체에 가려진 손끝 복원 |
| **로봇 장갑** | 손등 배치형 **5손가락 공압 벨로우즈 장갑** | 건손이 움직이면 마비손을 펴주고 쥐어줌. 손바닥은 뚫려 있어 촉각 유지 |
| **공압 제어** | 에어펌프 + 솔레노이드 밸브 5개 + ESP32 | 115200 bps로 실시간 가압/배기 |
| 프로그램 | Python + PyQt6/Tkinter + OpenCV | 4과제 자동 진행, 그래프, CSV/JSON 저장 |

**빠르기:** 카메라(16.6ms) + 손인식(15ms) + 계산(2ms) + 전송(1ms) + 공기 충진(35ms) = **69.6ms**. 사람이 "즉시"라고 느끼는 100ms보다 빨랐습니다.

#### (2) 그때 4개 과제 — 어떻게 했는지까지
1. **맨손 쥐었다 펴기** — 물체 없이. 왜? 물체를 쥐면 손이 물체에 기대는 반동이 생기는데, 그걸 빼고 **순수하게 손가락만 얼마나 움직이는지** 보려고. 또 물체가 없으니 **가림이 없어서** 이후 과제의 기준(캘리브레이션)이 됩니다.
2. **5cm 원통 잡기** — 캔·컵 같은 일상 파지. **ARAT Grip(2번 소검사)** 표준 규격.
3. **7cm 공 잡기** — 엄지가 3D로 맞서는(대립) 능력. **Jeannerod 법칙**의 "손 벌렸다가 닫기"를 봅니다. FMA-UE 손 항목의 야구공 규격.
4. **공압장갑 미러테라피 (15분)** — 건손으로 자유롭게 훈련하면 마비손 장갑이 70ms 이내로 따라 움직입니다. **치료 전/후 변화**를 즉시 계산.

**하는 방법:** 양손을 동시에 뻗어 → 잡고 → **5cm 들어올리고 → 2초 유지 → 내려놓기**, **8번 반복**.
**왜 8번?** 워밍업 2~3번을 버리고도 안정된 값(신뢰도 0.85 이상)을 얻으려면 최소 5번이 필요. 그런데 이 단계 환자는 **10~12번을 넘으면 손이 지쳐서 경직이 올라오고 몸통으로 보상**합니다. 그래서 8번이 딱 좋은 균형점.

#### (3) 왜 4개였나 — "브룬스트롬 단계와 1:1"
브룬스트롬은 뇌졸중 회복 단계입니다. 손 단계 3→4→5가 딱 "덩어리로 움직이다가 손가락을 따로 쓰기 시작하는" 경계입니다.
- **3단계** = 주먹은 쥐지만 못 폄 → **1번(맨손)**
- **4단계** = 굵은 물체를 감쌀 수 있음 → **2번(원통)**
- **5단계** = 공을 잡고 손가락을 펼 수 있음 → **3번(공)**
- (+ **4번** = 로봇으로 치료)

그래서 "FMA-UE 손 7개 항목 + ARAT 파지 영역을 **100% 대변**"한다고 주장했습니다.
**일부러 뺀 것:** 손끝 집기(tip pinch, 중등도 환자는 못 하고 카메라로도 손끝이 겹침), 측면 집기(key grasp, 2D라 단순), 원판 집기(손목 각도에 너무 민감, 손가락 70%가 가려짐).

#### (4) 물건 규격
- 원통: 지름 **5.0cm**, 높이 12cm(나중에 10cm), 무광 목재
- 공: 지름 **7.0cm**(야구공 크기), 무광 목재
- (나중에 추가) **측면집기 블록**: 두께 **1.5cm** × 폭 4cm × 높이 7cm — 4단계 판별용. 앞뒤 방향으로 세워서 **엄지-검지 벌림이 위에서 내려다보는 카메라에 정면으로 보이게** 했습니다.

#### (5) 사람과 윤리
- **비장애인 15명**(20~65세) + **뇌졸중 15명**(발병 3개월 이상)
- 장애인 조건: **브룬스트롬 3~5단계**, **FMA-UE 손 20~55점**, MMSE 24점 이상
- 제외: 손 관절이 50% 이상 굳음, 편측 무시, 상처
- **병원 IRB(에스포항병원 등) 승인** + 서면동의 + 공압 안전장치(압력 제한 밸브, 비상정지)
- 표본: G*Power로 계산(효과크기 0.65~0.75, 검정력 80%) → **최소 13~21명 → 탈락 고려 30명**

#### (6) 그때 재던 숫자 (수식 뜻풀이)
- **14개 손가락 관절 각도** — 벡터 사이 각도(코사인)로 계산
- **TAM**(총 능동 운동범위) — 다섯 손가락이 각각 얼마나 움직였는지 전부 더한 값 (미국수부외과학회 표준)
- **MGA Ratio** — 최대 손 벌림을 손바닥 길이로 나눠서 사람 크기 보정 (Jeannerod 법칙)
- **SPARC** — 움직임이 얼마나 매끄러운지(경직·떨림) 점수
- **SI(대칭도)·τ_lag(지연)** — 좌우가 얼마나 같이 움직이는지, 시간차

#### (7) 그때 AI는 2단계였습니다 (지금과 다른 점)
- **1단계(예전 AI):** 관절각 10초치(300프레임 × 24개)를 **1D-CNN + BiLSTM**에 넣어 → 브룬스트롬 분류 + FMA 점수 회귀 + 이상 감지
- **2단계(VLM):** 확정된 점수 + 핵심 장면 → **임상 소견서** 작성
- **왜 VLM 단독으로 안 했나:** 원문 그대로 — *"VLM에 영상만 주고 FMA 점수를 매기라 하면 매번 달라지는 임의의 수치를 생성(hallucination)하여 의료기기로서의 신뢰성을 상실"* 합니다. 그래서 **숫자는 1단계가 확정하고, 말은 2단계가 하는** 분리 구조였습니다.
- **지금은?** 오히려 **"VLM이 점수를 매길 수 있는가"** 를 실험 대상으로 바꿨습니다. 그래서 VLM이 주인공이 됐습니다.

#### (8) 30분 세션 흐름
① 수기 FMA + 각도계(5분) → ② 컴퓨터 평가 1~3번 각 3회(5분) → ③ 공압 미러테라피(15분) → ④ 다시 평가 1~3번(5분).

#### (9) 사실 9월 4일에 이미 방향이 바뀌기 시작했습니다
옛 영문 제안서(9/4, "Final Methodologically Verified Edition")에 이미 **6가지가 바뀌어** 있었습니다:
1. **카메라를 로봇 구동에서 완전히 분리**(진단 전용) — 렉과 가림 때문에
2. 장갑 vs 표준요법 **동등성 비교 → "추가요법(add-on)" 설계**로 (윤리)
3. 중재 전 1회 → **baseline + 4주 후 2회** 측정
4. **"미세 손가락 분리도는 잡음 때문에 제외"** → 거친 운동학 + VLM
5. 단독 카메라 모델 → **3-Arm 비교**(영상만 / 영상+운동학JSON / 제안)
6. 정확도·AUC → **비모수 통계 + Spearman**

즉 **"손가락 하나하나를 다 보겠다"는 처음부터 포기**하고 있었습니다. 그리고 **VLM 점수 평탄화(arXiv:2511.17727)** 를 이미 인용하고 있었습니다.

- **통계**: **환자별 (A2 − A1) 오차 차이**, 환자 단위 부트스트랩

→ 지금의 **A1/A2/A3/R + M1~M4 + JSON + 비장애 참고분포**의 **직계 조상**입니다.

> **한 줄:** **"수치를 AI에 넣는다"는 핵심 아이디어는 원래부터 있었고**, 바뀐 것은 **"무엇을 재는가"(FMA→ARAT)** 와 **"몇 개 과제인가"(4→2→3)** 입니다.

### 1-3. "그 논문이 뭘 했길래 이 과제를 골랐나" (쉬운 판)

이재용 님이 궁금해하신 부분입니다. **과제 하나하나가 왜 그렇게 정해졌는지**, 그 뒤에 있는 논문과 **그 논문이 실제로 한 일**을 쉬운 말로 정리했습니다.

| 과제 | 이 논문을 보고 | 그 논문이 한 일 |
|---|---|---|
| **맨손 쥐기/펴기** | 뇌졸중 연합반응 연구 + FMA | "하나만 굽히려 해도 옆 손가락이 따라 굽는" 현상을 정량화 |
| **5cm 원통** | **Lyle 1981** + **Yozbatiran 2008** | ARAT 검사의 **Grip(쥐기) 소검사 표준 원통 = 지름 5cm** |
| **7cm 공** | **Fugl-Meyer 1975** + **Jeannerod 1984** | FMA 손 검사의 **공 잡기 = 야구공(6.5~7cm)** / 사람은 물건보다 **1.2~1.5배 크게** 손을 벌렸다가 잡음 |
| **공압 미러테라피** | **Chen 2025** | 건손을 따라 로봇이 마비손을 움직이는 **미러테라피 로봇** |
| **부드러움 점수(SPARC)** | **Balasubramanian 2015** | "부드러움" 재는 공식 32개 중 **딱 하나(SPARC)만 쓸 만하다**고 정리 |
| **손 크기 보정 점수(MGA)** | **Jeannerod 1984** | 손 벌림이 물건 크기에 비례한다는 법칙 |
| **카메라로 손가락까지** | **Amprimo 2024**(GMH-D) | 카메라+깊이로 손끝 거리를 모션캡처와 비교해 **맞는다고 검증** |
| **"우리는 손가락 미세운동 한다"** | **Kim 2016** | 카메라로 FMA를 채점했지만 **팔 대동작만** 했고 **왜 그런지 설명 못 함** |
| **블록·구슬로 바꾼 이유** | **Unger 2026** + **Padilla-Magaña 2022** | 카메라는 "**했냐/못했냐**"는 잘 가르지만 "2점/3점"은 못 가림 / ARAT 16활동은 **이미 다 해봄** |

#### 하나씩 자세히

**① 왜 "맨손" 과제를 넣었나**
물건을 쥐면 손이 물건에 기대는 힘이 생기고, 손이 물건에 가려집니다. 그래서 **아무것도 안 쥐고** 손가락만 최대한 쥐었다 펴게 해서 ⑴ 순수하게 손가락 힘만 얼마나 나오는지, ⑵ **한 손가락만 움직이려 해도 옆 손가락이 같이 움직이는지**(뇌졸중의 대표 증상), ⑶ 나중에 물건 과제에서 가려진 손끝을 복원할 **기준값**을 얻었습니다.

**② 왜 "지름 5cm 원통"인가** — 이게 제일 놀라운 부분입니다
**Lyle 1981**이 만든 ARAT 검사(지금도 쓰는 표준)의 **Grip 소검사**가 바로 **지름 5cm 원통**입니다. 그래서 우리도 같은 규격을 쓰면 **국제 표준 검사와 직접 비교**가 됩니다. 게다가 **음료수 캔(5.2cm), 종이컵(5~7cm), 문손잡이**와 비슷해서 일상생활과 연결됩니다. 높이 12cm는 손가락이 감싸 쥐는 높이, **무게 150g**은 "이 정도는 들어야 손이 물건을 느낀다"는 최소 무게였습니다.

**③ 왜 "지름 7cm 공"인가**
**Fugl-Meyer 1975**(FMA 원논문)의 손 검사에 **공 잡기**가 있는데 그게 **야구공/테니스공 크기(6.5~7cm)** 입니다. 그리고 **Jeannerod 1984**가 발견한 게 핵심입니다 — 사람은 물건을 잡을 때 **물건보다 1.2~1.5배 크게** 손을 벌렸다가 닫습니다. 즉 **7cm 공이면 정상인은 8.5~10.5cm까지 벌립니다.** 뇌졸중 환자는 이걸 **너무 조금 벌리거나(과소) 너무 많이 벌리는데(과대)**, 7cm가 그 차이가 **가장 잘 드러나는 크기**였습니다.

**④ 왜 "미러테라피"를 과제로 넣었나**
**Chen 2025**가 건손 움직임을 로봇으로 마비손에 따라 하게 하는 연구를 했습니다. 다만 그건 **팔 전체 로봇 + 근전도 센서**라 무겁고, **손가락 세부 지표는 없었습니다.** 우리는 **가벼운 공압 장갑 + 손가락 세부 지표**로 차별화했습니다.

**⑤ 왜 이 3개는 **뺐나**
- **손끝 집기(tip pinch)** — 중등도 환자는 아예 못 하고, 카메라로도 **손끝이 겹쳐서** 못 봅니다.
- **측면 집기(key grasp)** — 엄지를 검지 옆에 대는 **2D 단순 동작**이라 5손가락 협응을 반영 못 하고, 검지에 가려 각도가 안 보입니다.
- **원판 집기(disk grasp)** — 손목 각도에 너무 민감하고, **손가락 70%가 가려집니다.**

**⑥ 물건 크기·무게·재질은 왜?**
- **무광(maté) 재질**: 반짝이면 카메라가 손을 잘못 봅니다(**반사율 5% 미만**).
- **마찰계수 약 0.6**: 미끄러지면 값이 흔들립니다.
- 원통은 **MCP 45°·PIP 70°·DIP 40°** 로 자연스럽게 감싸지도록, 공은 **엄지가 35° 넘게 안쪽으로 돌아가야(대립)** 하도록 크기를 정했습니다.

**⑦ 숫자들은 왜 이걸 쓰나**
- **TAM**(총 가동범위) = 미국수부외과학회 표준. 정상은 약 450°, 환자는 250° 미만.
- **SPARC**(부드러움) = 부드러운 공식 32개 중 **유일하게 살아남은 것**.
- **MGA**(손 벌림) = 손 크기·카메라 거리에 안 흔들리게 **손바닥 길이로 나눠서** 씁니다.

**⑧ "정답"은 뭘로 했나**
- 손 각도 정답 = **각도계(고니오미터)** → 카메라가 이걸 맞히나(일치도 0.85 이상)
- 점수 정답 = **치료사 2명이 따로 매긴 FMA/Brunnstrom**
- 품질 정답 = **가림을 사람이 표시한 것**

**⑨ 그런데 왜 지금은 "블록·구슬"로 바뀌었나**
**Unger 2026**이 실제 병원 ARAT에 카메라를 달아보니, 카메라는 **"했다/못했다"는 잘 가르는데(정확도 0.96~0.99), "2점이냐 3점이냐"는 못 가립니다(0.70~0.84).** 그래서 **"완수 vs 실패"가 잘 드러나는** ARAT **3번(블록) + 12번(구슬)** 로 좁혔습니다. 그리고 **Padilla-Magaña 2022**가 이미 **ARAT 16개 활동**을 다 해봤기 때문에, 우리가 "처음"이라고 하면 안 됩니다. → **더 좁고 깊게** 가는 것이 우리 자리입니다.

> ⚠️ **중요:** 블록·구슬 점수를 **더해서 임상 점수(0~6점)처럼 쓰지 않습니다.** 두 과제는 **조건을 공평하게 비교하기 위한 고정 도구**입니다.

## 2. 왜 방향을 바꿨나 — "이미 남이 한 것"과 "우리만 할 수 있는 것"

### 2-1. 제일 아팠던 순간 (9월 23일)

처음엔 "아무도 안 한 연구"라고 생각했습니다. 그런데 논문을 **체계적으로 뒤져보니**, 우리가 "비어 있다"고 한 3가지가 **전부 이미 있었습니다.**

| 우리가 한 말 | 실제로는 |
|---|---|
| "카메라로 손가락까지 검증한 사람이 없다" | **Amprimo 2024** 가 이미 했다 |
| "화질 품질 규칙(게이팅)은 없다" | **EVGS 2025** 등이 이미 했다 |
| "가림(가려짐) 실패를 정량화한 사람이 없다" | **Hand Visibility Detector** 가 이미 했다 |

특히 아팠던 건, 그중 하나(**Amprimo 2024**)가 **사용자(이재용) 메모에 이미 적혀 있던 논문**이었다는 점입니다. "내가 다시 안 읽고 '빈 곳'이라고 썼다"는 걸 인정하고 기록했습니다.

### 2-2. 그래서 살아남은 것 (우리 자리)

무작정 "우리가 처음이다"라고 하면 안 되니, **진짜 비어 있는 것만** 남겼습니다. 그게 **"여러 조건을 똑같이 두고, 숫자를 줬을 때/안 줬을 때/품질 나쁜 숫자를 뺐을 때 점수가 어떻게 달라지는가"** 를 **처음으로 측정**하는 일입니다.

표현을 이렇게 고정했습니다: **"우리가 처음 만든 게 아니라, 처음 측정한다."**

### 2-3. 나머지 방향 전환

- **ARAT 2개 과제**(블록 3번, 구슬 12번)로 시작 → 나중에 3개로 늘림(교수님 피드백)
- **"손가락 벌림을 영상만 보고 맞힐 수 있다"** 는 주장은 버림. 다른 논문(**Li 2022**)이 카메라로 손목 위치를 재면 **평균 9.6cm나 틀렸다**고 보고했고, 우리가 보려는 **구슬은 1.6cm**밖에 안 됩니다. 즉 **원리적으로 불가능**에 가깝습니다.

## 3. 실수를 찾아 고친 큰 사건들

### 3-1. 없는 논문을 인용하고 있었다 (9월 25일)

우리 문서에 넣은 논문 출처(DOI)를 **전부 자동으로 검사**했습니다. 결과:

- **증거맵 2종·계획서는 깨진 인용 0건** ✅
- 그런데 **캡스톤 분석보고서 5개에는 25건의 문제**가 있었습니다. 그중 **8건은 "링크는 열리는데 전혀 다른 논문"** 이었습니다.
  - 예: "손 정밀도 논문"으로 적은 링크가 **차량용 토양 측정기** 논문이었고, "PREP2 논문"은 **알츠하이머 뇌네트워크** 논문이었습니다.
- **무서운 점:** 링크를 눌러도 열려서 **눈으로는 안 보입니다.**

**고친 방법:** 실존하는 올바른 논문으로 16건 교체, 10건은 "미검증" 딱지를 붙여 보존(억지로 안 만듦). **"캡스톤 보고서 5개는 외부에 내보내지 말 것"** 이라고 기록했습니다.

### 3-2. 시계가 고장 나 있었다 (9월 25일 ~ 9월 28일)

이건 하마터면 **결론을 통째로 잘못 잡을 뻔한** 사건입니다.

- 데이터에 **손이 초당 7.9m(시속 28km)로 움직였다**는 값이 있었습니다. 사람 손은 그렇게 빠르지 않습니다(정상 초당 0.3~0.8m).
- 원인을 파보니 **운동이 아니라 시계 오류**였습니다.
  - 컴퓨터가 **벽시계**로 시간을 재는데, 같은 순간이 여러 번 찍혀서 **시간 간격이 1/34로 줄어들었고**, 그 상태로 속도를 계산하니 값이 **10억 배**로 폭발한 것입니다.
  - **프레임 시계**로 다시 계산하니 **0.605m/s** (정상)로 돌아왔습니다.
- 이 과정에서 **내(파인만) 결론을 3번 뒤집었습니다.** "P95는 안정적이다", "화면 렉 때문이다", "SPARC가 통과한다"고 했다가, 검증 결과 **전부 틀렸음**을 인정하고 철회했습니다.
  - 예: "SPARC 통과"는 손을 **좌우로 나눠보니 오른손이 기준 초과**였는데, **양손을 평균 내서 가려졌던 것**입니다.

**배운 교훈 3가지:**
1. **최댓값(peak)은 못 믿는다. 대신 P95(상위 5%)를 쓴다.**
2. **시계를 먼저 정해야** 품질 판정을 할 수 있다.
3. AI가 만든 분석도 **"내가 틀렸다"를 반복**할 수 있으니 계속 검증해야 한다.

### 3-3. 코드가 계획과 **다른 실험**을 하고 있었다

계획서에는 "K1·K2 두 숫자"를 쓴다고 썼는데, **실제 코드는 4개를 쓰고 과제도 달랐습니다.** 문서와 코드가 다르면, 촬영 후 "무엇을 넣었는지" 재구성할 수 없습니다. → **문서와 코드를 1:1로 맞추는 것**을 원칙으로 세웠습니다.

### 3-4. 말 바꾸기 (9월 25일, 사용자 지시)

"건강인" → **"비장애인"**, "환자" → **"장애인"** 으로 문서 80여 개를 고쳤습니다. 이때 **데이터 폴더 이름 같은 건 실수로 바꾸면 안 되므로** 5곳은 원래대로 보존했습니다.

## 4. 교수님 질문이 바꾼 것 (10월 1일)

교수님이 두 가지를 물으셨습니다.

> (1) **왜 ARAT 2개 과제만 하냐? 그걸로 충분하냐?**
> (2) **손 움직임만 보는 게 맞냐? 상체를 봐야 하지 않냐?**

### 4-1. 가장 중요한 발견 — "체간(몸통)은 원래 채점 기준이었다"

교수님 질문을 검증하다가 **ARAT 공식 채점표 원문**(Yozbatiran 2008)에서 이런 문장을 찾았습니다:

> *"몸통이 의자 등받이에서 완전히 떨어지면 → 2점."*

즉 **몸통은 우리가 "추가로 넣고 싶은 지표"가 아니라, ARAT 규칙이 이미 요구하는 정보**였습니다. 그런데 우리 계획은 **몸통을 카메라로 보이게 하지도, AI에 알려주지도 않았습니다.** → 교수님 질문은 "범위를 늘려달라"가 아니라 **"채점 근거 하나가 빠져 있다"** 는 지적이었습니다.

### 4-2. 그래서 바뀐 것
- 과제 **2개 → 3개** (블록, 구슬, **손바닥 머리 위에 대기**)
- **몸통(체간) 변위**를 숫자에 추가
- 촬영 앱에 **몸통 인식(Pose)** 기능을 새로 넣음 (원본 앱은 안 건드리고 새 모듈만 추가)

| **숫자 4개** | 손 벌림, 손가락 굽힘 합, 손목 부드러움(SPARC), 몸통 변위 |
| **AI 모델** | Qwen2.5-VL-32B (주), 비교용 4개 |
| **주 질문 3개** | ① 숫자를 주면 좋아지나 ② 품질 나쁜 건 빼면 좋아지나 ③ 그냥 개수만 맞춰 빼는 것과 뭐가 다른가 |
| **기간·예산** | 10주, 공식 15만원 + 사비 상한 15만원, RTX 5090 |

**중요:** 이 실험은 **"점수를 새로 만드는 것"이 아니라 "치료사 점수를 AI가 더 잘 따라가는지"** 를 보는 것입니다.

## 6. 카메라 하나로 무엇을 믿을 수 있나 (쉬운 결정표)

가장 자주 나오는 질문: **"카메라 하나로 어떻게 품질을 아느냐?"**
답: **알 수 없습니다. 그래서 "정확도"가 아니라 "믿을 만한가"를 잽니다.**

| 무엇을 | 믿을 수 있나 | 이유 |
|---|---|---|
| 팔꿈치·어깨 각도 | **믿을 만함** | 다른 연구에서 ICC 0.92~0.94 (거의 완벽에 가까움) |
| 동작 시간 | **믿을 만함** | ICC 0.76 |
| 몸통이 앞으로 나온 거리 | **조건부** | ICC 0.93이지만, **몸통 중심이 기준이라 "이동 거리"는 원래 못 잡음** → 정지 2초 기준선을 꼭 찍어야 함 |
| 몸통 회전 | **못 믿음** | ICC 0.38 (낮음) |
| 손목 순간 속도(최고속도) | **못 믿음** | ICC 0.21 (사실상 실패) |
| 속도 봉우리 개수 | **못 믿음** | ICC 0.38 |
| 부드러움(SPARC) | **아직 모름** | 지금까지 **아무도 카메라로 검증한 적 없음** → **우리가 처음 시도** |
| 손가락 벌림(구슬) | **원리적으로 어려움** | 카메라 손목 오차 9.6cm vs 구슬 1.6cm |

**비유:** 카메라는 "큰 움직임(팔 각도, 시간, 몸통 위치)"은 잘 보지만, **"빠르고 미세한 움직임(손목 속도, 부드러움)"은 잘 못 봅니다.** 그래서 우리는 **부드러움(SPARC)을 정면으로 도전**하는 것이고, 그게 이 연구의 핵심 기여입니다.

## 10. 어려운 말 사전

| 말 | 쉬운 뜻 |
|---|---|
| **ARAT** | 손 기능 검사. 19개 항목, 0~3점. 우리는 3번(블록)·12번(구슬) 사용 |
| **FMA-UE** | 상지 운동 기능 검사(0~66점) |
| **VLM** | 영상+글을 같이 이해하는 AI (예: Qwen2.5-VL) |
| **운동학(kinematics)** | "어떻게 움직였나"를 숫자로 표현한 것 (각도·속도·부드러움) |
| **SPARC** | 움직임이 얼마나 **부드러운지** 재는 점수 (0에 가까울수록 매끄러움) |
| **MGA** | 최대 손 벌림 |
| **ICC** | 두 측정이 얼마나 일치하는지 (1에 가까울수록 좋음, 0.75 넘으면 좋음) |
| **MDC** | "믿을 만한 최소 변화량". 이보다 작은 변화는 측정오차로 봄 |
| **게이팅(gating)** | 품질이 나쁜 데이터를 **걸러내는 것** |
| **보류(abstention)** | 확신이 없으면 **판단을 안 하고 넘기는 것** |
| **GMM** | 움직임 패턴을 **여러 무리로 나누는** 통계 방법 |
| **체간(trunk)** | 몸통. ARAT에서 **등받이에서 떨어지면 감점** |
| **오라클(oracle)** | "정답을 아는 합성 데이터"로 코드가 맞는지 확인하는 검사 |
| **평탄화(flatlining)** | AI가 누구에게나 비슷한 점수를 주는 현상 |
